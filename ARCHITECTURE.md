# &lt;3 (Heart3) — Architecture — 3.0.0

## Рабочие точки входа

`python -m device.run_android`, `device.run_ios`, `device.run_mac` — отдельные
циклы одного устройства: снимки и bio → vision-агент → порог → действие.
Android использует uiautomator2; iPhone и iOS Simulator — Appium/XCUITest.
Импорты SDK и логика проверяются без устройства, актуальные селекторы — нет.

`python main.py` — экспериментальный API-runtime одного Twinby-аккаунта:

```text
Settings → DatabaseManager → TwinbyStealthClient
         → Telegram-пульт → start/stop SwipeWorker
         → локальный FastAPI с REST и WebSocket
         → бэкап файловой SQLite-базы по DATABASE_URL
```

Worker стартует только по команде администратора. Внешние dating API проверены
моками, не живыми контрактами. Схема БД не разделяет аккаунты и платформы:
для каждого аккаунта нужна отдельная база; multi-process/multi-account запуск
не поддерживается.

## Обработка анкеты

Внутри процесса общий `DatabaseManager.swipe_lock` сериализует обработку:

```text
проверка target_user_id → нативный или текстовый LLM-скоринг → фильтры
→ пауза → повторная проверка дневного бюджета LIKE
→ commit намерения → единственный внешний запрос → обновление результата
```

Неопределённый результат остаётся pending/uncertain в поле `reason`, занимает
бюджет и запрещает повтор той же анкеты. Статистика считает попытки, не только
подтверждённые действия. Автоматического повторения неопределённых POST нет.
Этот механизм не является межпроцессной транзакцией с внешним сервисом.

При ошибке AI-скоринга эвристическая оценка остаётся только диагностикой;
worker выбирает PASS независимо от установленного порога. Нативный процент
не проверяет спам. `require_bio` проверяет непустой текст. Пороги API/device
равны 75 только по умолчанию; ровно 75 допускает LIKE.

## Реестр и адаптеры

`GLOBAL_DATING_REGISTRY` — 28 спецификаций с метками 10 direct API / 12 hybrid /
6 UI-only. Метки отражают проектные предположения, не доказанную совместимость.
Фабрика создаёт только Twinby/Pure/Tabor; для остальных возвращает явную ошибку,
а не притворяется, что произвольный сервис имеет одинаковые REST-маршруты.

Экспериментальный `MobileUIDriverFallback` умеет открыть Android Appium-сессию
и отправить действие. В нём нет чтения анкет, iOS capabilities и обнаружения
мэтчей. Без сессии или при ошибке HTTP действие не считается успешным.
UI-only без драйвера не переключается самовольно на API.

## Независимые AI-компоненты

`UniversalAIGateway` реализует OpenAI-совместимый протокол и Anthropic Messages.
URL, ключ и модель задаются вручную. Gemini поддерживается через совместимый
endpoint `/openai`, не через нативный API. Прокси окружения не наследуются.

`DatingLangGraphEngine`: контекст анкеты → черновик → редактор, максимум два
прохода редактора (один возврат). История сохраняет роли user/assistant;
данные анкеты отделяются от системных инструкций. Возвращает текст и handoff-флаг,
но не отправляет сообщения и не вызывает календарь.

`PromptThompsonBandit`: Beta(1,1), транзакционная запись результатов в Redis;
выбор и обратная связь требуют явного вызова. `book_dating_event_tool` — отдельное
создание 90-минутного события с OAuth и часовым поясом Europe/Moscow.
Ни один из этих модулей не включён в post-match цикл `main.py`.

## Границы доступа и данных

- Telegram: только явно известный `TG_ADMIN_ID`; отсутствие identity запрещено.
- REST/WS: отдельный непустой `WEB_ADMIN_TOKEN` в Authorization Bearer;
  Telegram credential и query-token не принимаются. Пустой web-секрет запрещает доступ.
- WebSocket рассчитан на клиенты с заголовками; браузерной панели управления нет.
- Корень web — публичная витрина. Worker не публикует события в WebSocket-шину.
- Сервер по умолчанию доступен только через loopback; для внешнего доступа необходимы TLS и ограничения.
- SQLite backup открывает только существующий источник read-only. Для memory/других СУБД отключён.
  Отправка бэкапа администратору раскрывает его содержимое Telegram.
- Фото/bio при AI-анализе покидают устройство; это нужно учитывать до запуска.

## Проверки и ограничения доказательств

Тесты исполняют реальные циклы с подставными устройствами, проверяют контракты
запросов, авторизацию, ошибки, лимиты и содержимое витрины. Native curl блокируется
до коллекции; для адаптеров используется httpx/respx, Python-соединения ограничены
pytest-socket. Локальные ключи и `.env` не используются. Это не OS-level изоляция.

Ни мокированные контракты, ни количество тестов, ни реестр сами по себе не доказывают
работоспособность реальных dating API, селекторов устройства или защиту от блокировки.

# Changelog — 3.0.0

Все заметные изменения проекта. Формат — Keep a Changelog.

## [3.0.0] — 2026-11-19 (не опубликовано)

### Added
- Экспериментальное API-ядро одного Twinby-аккаунта: worker, фильтры, SQLite,
  Telegram-пульт и защищённые REST/WebSocket endpoints.
- Реестр 28 спецификаций (10 direct API / 12 hybrid / 6 UI-only).
  Эти метки не доказывают поддержку сервисов; живые API не проверены.
- Отдельные клиенты Twinby/Pure/Tabor и экспериментальный Android Appium-драйвер.
- Независимые AI-модули: LLM gateway, LangGraph, Redis Thompson Sampling,
  Google Calendar. К мэтчам и основному циклу они не подключены.
- Тесты реальных циклов с подставными устройствами, контрактов HTTP,
  авторизации, лимитов, бэкапов, AI-протоколов и достоверности витрины.
- Шаблон окружения, явная сборка Python-пакетов и включение web-статики в wheel.
- Dockerfile и сохранение SQLite в volume вместо compose с отсутствующим Dockerfile.

### Changed
- Продукт переименован в `<3` (Heart3), Python distribution — `heart3`.
  Обновлены витрины, метаданные, CLI-баннеры, Telegram-пульт и OpenAPI.
  Старые GitHub URL и пути существующих данных сохранены до отдельной миграции.
- Повторно сверен heart3-project-complete.zip: архив не заменяет исправленный код
  и не подтверждает заявленные в нём InsightFace, Temporal и автопереписку.
- Старые драйверы сохранены в `device/`: запуск через `python -m device.run_android`
  (аналогично `run_ios` / `run_mac`).
- Пороги API/device по умолчанию 75, но настраиваются независимо;
  граничное значение 75 допускает LIKE.
- Worker записывает намерение до внешнего запроса. Неопределённый исход занимает
  бюджет попыток и не повторяется автоматически. Межпроцессной гарантии нет.
- Неизвестные адаптеры фабрика отклоняет вместо фиктивного универсального REST-клиента.
- Витрина сохраняет bubble-дизайн, но отделяет работающий код от экспериментов
  и неподтверждённых интеграций. Исправлены обрезание мобильных заголовков,
  контраст мелкого текста и клавиатурный фокус.
- Тесты заменяют inherited credentials, отключают dotenv и блокируют native curl
  до коллекции. Python socket-guard не объявляется OS-level песочницей.

### Fixed
- Чистая установка SQLAlchemy 2.1: явно включён extra `asyncio` с greenlet;
  ранее глобальное окружение скрывало недостающую runtime-зависимость.
- iPhone/Mac: неверный импорт `XCUITestOptions`, скрытый прежними тестовыми заглушками.
- Дневной бюджет проверяется перед каждым LIKE, а не только перед пачкой из 15 анкет.
- Ошибка скоринга теперь приводит к PASS даже при пониженном пороге.
- `REQUIRE_BIO` действительно проверяет непустое описание.
- SQLite создаёт родительский каталог; бэкап берёт путь из `DATABASE_URL`,
  не создаёт пустой источник и корректно закрывает соединения при остановке.
- UI-only без драйвера не падает в API; отсутствие Appium-сессии и ошибки HTTP
  не маскируются успешным dry-run.
- Web использует отдельный `WEB_ADMIN_TOKEN`, пустые credentials не авторизуют.
  WebSocket больше не принимает долгоживущий секрет в URL. По умолчанию bind loopback.
- Telegram: неизвестный отправитель запрещён, имя анкеты экранируется для HTML,
  callback-запросы подтверждаются.
- Anthropic: обязательный `max_tokens`, системные сообщения в правильном поле,
  версия протокола независимо от формата авторизации.
- LangGraph сохраняет роли истории, отделяет инструкции от данных, корректно
  обрабатывает отказ редактора без текста замечания и ограничивает цикл.
- Calendar читает OAuth из Settings и не блокирует event loop синхронным SDK.
- Redis bandit сохраняет prior Beta(1,1) при первом результате.
- Httpx не наследует системный proxy/NO_PROXY; некорректный `[::1]` больше не ломает шлюз.
- Фикстура HTTP-транспорта поддерживает request и обновление auth-заголовков;
  тесты порога исполняют продуктовый код, а не копию условия.

### Removed
- Неиспользуемые CV-зависимости и заглушки из архива (InsightFace/CLIP-инференса нет).
- Неиспользуемые настройки `llm_enabled`, `auto_send_icebreaker` и мёртвые поля фильтра.
- Обещания 28 рабочих интеграций, автоматической переписки, готовой браузерной
  панели и защиты от блокировок: реализация и проверка этого не подтверждают.
